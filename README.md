# 黄金每日趋势预测系统

> 全自动黄金每日预测系统——每天自动预测、自动验证对错、自动部署到线上面板。
>
> 线上面板（GitHub Pages 部署）：当日预测结论、实时金价、60 日走势、历史胜率、要闻聚合，手机浏览器直接看。

---

## 一、预测口径（操作手册）

本节是整套系统的"宪法"，所有脚本和定时任务都以这些规则为准绳。

### 1.1 预测窗口

| 项目 | 定义 |
|------|------|
| 预测对象 | 北京时间当日 06:00 → 次日 06:00 的 XAU/USD（伦敦金现）当日趋势 |
| 覆盖范围 | 当日全天交易时段，含亚盘、欧盘、美盘 |
| 生成时间 | 每日 06:30（北京时间）定时生成，预测的是"今天"的走势 |
| 结算时间 | 次日 06:30 流水线自动结算（回填实际价、自动打分） |

### 1.2 方向二分

| 方向 | 定义 |
|------|------|
| 涨 | 次日 06:00 实际价 > 当日 06:00 基准价 |
| 跌 | 次日 06:00 实际价 < 当日 06:00 基准价 |
| 平 | 实际恰好持平；该日方向不计对错（罕见） |

### 1.3 幅度三档

| 档位 | 条件 |
|------|------|
| 小 | \|涨跌幅\| ≤ 0.3% |
| 中 | 0.3% < \|涨跌幅\| ≤ 1.0% |
| 大 | \|涨跌幅\| > 1.0% |

### 1.4 计分规则

- 次日 06:30 自动拿实际价对照基准价计算涨跌幅
- **方向对错**：预测方向 vs 实际方向，一致记 √，不一致记 ×
- **档位对错**：预测幅度档 vs 实际幅度档，一致记 √，不一致记 ×
- 分数只算"最终"列（经人工修正后的决策），模型原始值仅留档对照
- 若实际恰好持平（平），该日方向不计对错

### 1.5 人工修正

- 报告发出后如需改判，修改"最终方向/最终幅度档"并在"人工修正"列记"是"
- 模型原始方向/档位仅作对照留档，不计分，用于事后分析模型与人工修正各自贡献

### 1.6 市况标签

- 按近 20 个交易日区间与波动自动判定：趋势涨 / 趋势跌 / 震荡
- 仅作分组分析，不影响计分
- 判定逻辑：20 日累计涨跌幅 > 3% → 趋势涨；< -3% → 趋势跌；否则 → 震荡

### 1.7 置信度

- 晨间生成预测时，模型输出方向置信度（如"55% 把握"）
- 同步记入 log.xlsx 的"置信度(%)"列
- 攒够 20 个已结算样本后运行 `scripts/calibration.py` 出校准报告
- 校准目的：验证声称 55% 把握的日子，实际命中率是不是真的 55%

## 二、系统架构

```
gold-predictor/
├── README.md                     # 本文件——预测规则操作手册
├── API_KEYS_GUIDE.md             # API Key 获取指南
├── requirements.txt              # Python 依赖
├── dashboard/
│   └── dashboard.html            # 线上预测面板（GitHub Pages 部署）
├── log.xlsx                      # 评分日志（3 个 Sheet：日志/统计/说明）
├── scripts/
│   ├── utils.py                  # 共享工具（北京时间、周末守卫、Excel 读写）
│   ├── collect.py                # 数据采集（金价、VIX、汇率、新闻）
│   ├── predict.py                # 模型推理（方向+幅度+置信度 → 报告 → 部署）
│   ├── settle.py                 # 自动结算（回填实际价 → 打分 → 胜率统计）
│   ├── deploy.py                 # 部署（重新生成 dashboard.html → 推送 gh-pages）
│   ├── refresh.py                # 手动刷新（盘中触发采集最新价 → 更新面板）
│   └── calibration.py            # 置信度校准报告
├── .github/
│   └── workflows/
│       ├── morning.yml           # 06:30 晨间流水线（UTC 22:30 前一天）
│       ├── afternoon.yml        # 15:35 午后复核（UTC 07:35）
│       └── refresh.yml           # 手动刷新触发器（workflow_dispatch）
└── data/                         # 运行时数据（采集结果、中间文件）
```

## 三、每日运行流水线

### 3.1 晨间流水线（06:30 北京时间）

```
06:30 触发
  │
  ├─ 1. 结算昨日预测（settle.py）
  │     ├─ 获取昨日 06:00 → 今日 06:00 的实际金价
  │     ├─ 计算实际涨跌幅
  │     ├─ 判断实际方向和档位
  │     ├─ 回填 log.xlsx（实际价、涨跌幅、方向/档位对错）
  │     └─ 更新统计 Sheet（累计正确率、近 30 次正确率、分市况正确率）
  │
  ├─ 2. 采集今日数据（collect.py）
  │     ├─ 实时金价（gold-api）
  │     ├─ VIX 恐慌指数（CBOE / Yahoo Finance）
  │     ├─ USD/CNY 汇率（er-api）
  │     ├─ 新闻搜索（Tavily API）
  │     └─ 60 日价格序列（gold-api 历史数据）
  │
  ├─ 3. 模型推理（predict.py）
  │     ├─ 整理采集数据为推理上下文
  │     ├─ 调用 LLM API 推理方向 + 幅度档 + 置信度
  │     ├─ 生成大白话预测报告
  │     ├─ 写入 log.xlsx（新的一行）
  │     └─ 评估市况标签
  │
  ├─ 4. 部署面板（deploy.py）
  │     ├─ 读取 log.xlsx 最新数据
  │     ├─ 重新生成 dashboard.html（嵌入最新 JSON 数据）
  │     ├─ 推送到 gh-pages 分支
  │     └─ GitHub Pages 自动生效
  │
  └─ 5. 提交变更到主分支
        ├─ log.xlsx 更新
        ├─ dashboard/dashboard.html 更新
        └─ data/ 目录更新
```

### 3.2 午后复核（15:35 北京时间）

```
15:35 触发
  │
  ├─ 1. 获取实时金价
  ├─ 2. 更新 dashboard.html 的实时价格和追踪状态
  ├─ 3. 推送更新到 gh-pages
  └─ 注：不推翻早上的预测，仅更新实时价和追踪状态
```

### 3.3 手动刷新（随时）

```
用户点击面板"立即刷新"按钮
  │
  ├─ 1. 触发 GitHub Actions workflow_dispatch
  ├─ 2. 采集最新金价 + VIX
  ├─ 3. 更新 dashboard.html 实时数据
  ├─ 4. 推送 gh-pages
  └─ 限流：20 分钟内不可重复触发（localStorage 记录时间戳）
```

## 五、推理框架

采用世界黄金协会（WGC）短期金价归因框架加权：

| 因子 | 权重 | 说明 |
|------|:---:|------|
| 趋势与仓位动能 | 24% | 技术面信号、CFTC 持仓、ETF 流入流出 |
| 风险与不确定性 | 17% | VIX、地缘政治、避险需求 |
| 汇率与利率 | 14% | 美元指数、实际利率（TIPS）、Fed 政策预期 |
| 经济扩张 | 12% | GDP、PMI、通胀数据 |
| 随机扰动 | ~33% | 不可预测，诚实承认 |

## 六、实践经验总结

### 6.1 规则要沉淀在仓库里

定时任务每次都在全新沙盒里克隆仓库运行。只有把操作手册、口径、脚本全部固化进仓库，任务才能今天能跑、三个月后还能跑。

### 6.2 沙盒时钟是 UTC

所有日期判断必须显式转北京时间。踩过的坑：
- 周末休市守卫因为时区误判失效，周日当周一跑了采集
- 结算脚本里一个潜伏 bug，直到真实结算那天才暴露

### 6.3 定时系统必须幂等

- 重复跑不出错
- 出错敢重试
- 结算脚本用目标日期做幂等键，已结算的不重复结算

### 6.4 让 AI 系统自己给自己打分

预测如果只输出不验证，就只是每天一份新文案。自动结算 + 胜率统计 + 置信度校准这套闭环，才是这套系统里真正有价值的部分。

## 七、快速开始

### 7.1 本地运行

```bash
cd gold-predictor
pip install -r requirements.txt

# 设置环境变量
export TAVILY_API_KEY="your_key_here"
export LLM_API_KEY="your_key_here"
export LLM_BASE_URL="https://api.openai.com/v1"
export LLM_MODEL="gpt-4o"

# 手动跑一次完整流水线
python scripts/settle.py   # 先结算昨天
python scripts/collect.py  # 采集今天
python scripts/predict.py  # 推理 + 生成报告
python scripts/deploy.py   # 部署面板
```

### 7.2 GitHub Actions 部署

1. Fork 或创建仓库
2. 在 Settings → Secrets 中添加：
   - `TAVILY_API_KEY`
   - `LLM_API_KEY`
   - `LLM_BASE_URL`
   - `LLM_MODEL`
3. 启用 GitHub Pages（Settings → Pages → Source: gh-pages 分支）
4. 定时任务自动运行

### 7.3 面板访问

部署后访问：
```
https://<your-username>.github.io/<repo-name>/
```

## 八、log.xlsx 结构说明

### Sheet 1: 预测日志

| 列 | 字段 | 说明 |
|---|---|---|
| A | 目标日期 | 预测的交易日 |
| B | 生成时间 | 预测生成的时间戳 |
| C | 基准价($/oz) | 当日 06:00 切点金价 |
| D | 最终方向 | 涨/跌（经人工修正后的最终决策） |
| E | 最终幅度档 | 小/中/大 |
| F | 模型原始方向 | 模型输出值（留档对照） |
| G | 模型原始档位 | 模型输出值（留档对照） |
| H | 人工修正 | 是/否 |
| I | 次日实际价($/oz) | 次日 06:00 金价（结算时回填） |
| J | 实际涨跌幅 | (实际价-基准价)/基准价×100% |
| K | 实际方向 | 涨/跌/平 |
| L | 实际档位 | 小/中/大 |
| M | 方向对错 | √/× |
| N | 档位对错 | √/× |
| O | 市况标签 | 趋势涨/趋势跌/震荡 |
| P | 关键驱动摘要 | 利多利空信号综合 |
| Q | 备注 | 执行情况备注 |
| R | 置信度(%) | 模型置信度 |

### Sheet 2: 统计

- 已结算预测数
- 累计预测行数
- 方向/档位正确率（累计 + 近 30 次）
- 趋势市/震荡市方向正确率
- 置信度已记录数 / 已结算样本 / 校准报告门槛

### Sheet 3: 说明

规则说明文本，与本 README 第一节一致。
